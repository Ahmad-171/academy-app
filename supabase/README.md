# ترحيل الأمان — Supabase Auth + RLS

هذا الترحيل ينقل تسجيل الدخول من مقارنة كلمة سر نص صريح بالمتصفح إلى
Supabase Auth حقيقي، ويفعّل Row Level Security على كل الجداول. **شكل
تسجيل الدخول للمستخدم النهائي لا يتغير** (نفس رقم الهوية وكلمة السر).

⚠️ بعد إتمام هذه الخطوات، حسابات الدخول الحالية تعمل فقط بعد تشغيل
سكربت الترحيل — لا تشغّلها على بيئة فيها مستخدمون حقيقيون بدون تنسيق
مسبق.

## الترتيب (لا تغيّره)

1. **Supabase Dashboard → Authentication → Providers → Email**
   عطّل خيار **Confirm email** (الإيميلات المولّدة وهمية `{id}@academy.local`
   ولن تصل أي رسالة تأكيد).

   تحقق أيضًا من **Password Requirements → Minimum password length**:
   حسابات العرض التجريبي الحالية (111 / 221 / 331 ...) كلمات سرها ٣
   أحرف فقط. إما غيّرها بجدول `users` لتصبح ٦ أحرف فأكثر قبل الترحيل،
   أو خفّض الحد الأدنى من نفس الصفحة.

2. **SQL Editor** → شغّل `supabase/01_add_auth_column.sql` كاملاً.

3. **من جذر المشروع محليًا** (يحتاج `npm install` منجزة مسبقًا):
   ```
   node scripts/migrate-to-auth.mjs
   ```
   راقب المخرجات — لازم تشوف `✓` أمام كل حساب. أي `✗` يعني الحساب هذا
   ما اترحّل ولازم تحل السبب (غالبًا طول كلمة السر أو Confirm email).

4. تحقق بـ SQL Editor إن كل الحسابات ارتبطت:
   ```sql
   select id, name from public.users where auth_uid is null;
   ```
   لازم يرجع صفر صفوف. إذا رجع صفوف، أعد المستخدمين هذولا بالخطوة ٣.

5. **SQL Editor** → شغّل `supabase/02_enable_rls.sql` كاملاً.

6. **SQL Editor** → شغّل `supabase/03_finalize.sql` كاملاً (يحذف عمودي
   `password` و`medical` نهائيًا من جدول `users`).

7. اختبر تسجيل الدخول بنفس بيانات الحسابات التجريبية القديمة — لازم
   تشتغل بدون أي تغيير من طرف المستخدم.

## لو احتجت إضافة مستخدم جديد لاحقًا

الآن إنشاء حساب من لوحة المدير (تبويب "الحسابات" → "+ إضافة") يُنشئ
حساب Auth حقيقي تلقائيًا — ما تحتاج تكرر الخطوات أعلاه إلا مرة وحدة
للحسابات الموجودة حاليًا.
